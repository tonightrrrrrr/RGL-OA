# 反面案例说明

程序除了自带 10 份能全部识别成功的赛题示例，还准备了一组“反面案例”：故意让识别、解析、去重、命名出问题的文件，用来演示和验证程序遇到各种失败情况时的表现。

- 程序里的位置：绿色版解压后的 `示例文件\反面案例\`；源码里是 `src/main/resources/samples-negative/`。
- 模板设置页的“示例文件”下拉框里可以选“内置示例 · 反面案例”，直接看阈值、关键词规则对这些文件的影响。
- 每个文件的预期结果写在 `cases.json` 里，自动化测试 `NegativeSamplesTest` 会逐个检查，结果和这里写的不一致时测试会失败。
- 这些文件由 `NegativeSampleGenerator` 生成，内容都是虚构的。

## 怎么演示

1. 先在“导入识别”页导入 `示例文件`（10 份成功示例），点“预览并归档”，全部归档。
2. 再导入 `示例文件\反面案例`。结果应和下表一致：5 份待确认、3 份失败、2 份重复、2 份重名、2 份被跳过。
3. 到“待确认”页对照原文修正部门、日期后，这些文件就能归档；失败的文件可以“移除”，原文件不会被删除。
4. 归档时注意预览里“与本批次其他文件重名，归档时自动加序号”的提示。

> 如果没有先归档 10 份成功示例，“原材料采购框架合同（重复上传的副本）.pdf”会被正常识别，而不是判为重复，因为台账里还没有它的原件。

## 覆盖的情况

| 情况 | 文件 |
| --- | --- |
| 文件名没有含义（扫描件001、新建文档、IMG_xxxx） | 扫描件001.docx、新建 Microsoft Word 文档.docx、手机拍照_IMG_2045.png |
| 部门识别不出 / 置信度低 / 多个部门 | 扫描件001.docx、新建 Microsoft Word 文档.docx、会议纪要_待整理.docx |
| 没有日期或日期不完整 | 会议纪要_待整理.docx、备忘录.docx |
| 类型识别不出 | 备忘录.docx |
| 图片里没有文字（OCR 读不出） | 手机拍照_IMG_2045.png |
| 文件损坏 | 损坏的合同_2026-01-15.docx、损坏的报表_2026-02-28.xlsx |
| 加密文件 | 财务部_加密的薪酬明细_2026-03-31.pdf |
| 和台账里已归档的文件重复 | 原材料采购框架合同（重复上传的副本）.pdf |
| 同一批里有内容相同的文件 | 销售部_客户拜访记录表_2026-04-15.docx 和它的“ - 副本” |
| 新文件名重名 | 行政部_会议室使用管理规定_2026-05-06（一）（二） |
| 标题含 Windows 文件名不允许的字符 | 研发部_规划报告_2026-06-01.docx |
| Office 临时文件、空文件 | ~$临时文件.docx、空白文件.txt |

没有放进来的情况：超过大小上限（默认 200 MB）的文件太大，不适合放进安装包；解析超时（默认 120 秒）很难用小文件稳定复现。这两种情况在代码里有处理，见技术难点文档 4.6 节。
